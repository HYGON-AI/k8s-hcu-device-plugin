## 4.1 HAMi

HAMi 社区由来自 15+ 国家、350+ 贡献者共同维护，已被 200+ 企业与机构在实际生产环境中采纳，具备良好的可扩展性与支持保障。 HAMi 作为目前行业内唯一专注于异构 GPU 资源共享的开源项目，通过灵活、可靠、按需、弹性的 GPU 虚拟化来提升资源利用率，可以插拔式、轻量化、无侵入地部署在任意公有云、私有云、混合云环境中，可支持 海光、NVIDIA、昇腾、沐曦股份、寒武纪、摩尔线程，天数智芯、AWS neuron、燧原、昆仑芯 等异构芯片。并与 vLLM、Volcano、Kueue、Xinference 协同，数十家云厂商无缝集成。场景覆盖金融、物流、智驾、机器人、生物科技等行业，实现从 0 到 1 的落地。

Kubernetes集群通过设备插件HAMi模式HCU-Device-Plugin与HAMi调度器协同工作实现节点上vHCU的动态切分和自动回收。

### 4.1.1 HAMi模式HCU-Device-Plugin安装部署

建议给节点打上相应资源标签后使用HAMi模式HCU-Device-Plugin插件管理vHCU。

```
# 此项为固定标签,部署设备插件时需要查询此标签 
kubectl label nodes <node-name> hcu=on
```

详细安装部署方法参考《HCU-Device-Plugin组件vHCU动态切分模式安装部署》

HCU-Device-Plugin向k8s集群注册的vHCU资源名为hygon.com/hcunum，用户可以通过查看HCU节点k8s资源详情确认vHCU资源是否注册成功：

```
kubectl describe node <node-name>
```

如下为一个vHCU节点的资源注册实例，Capacity 字段中“hygon.com/hcunum: 4”表示该节点最多可分配4个可用vHCU资源。

```
Capacity:

  hugepages-1Gi:       0
  hugepages-2Mi:       0
  hygon.com/hcunum:    4
  memory:              131734840Ki
  pods:                110
Allocatable:
  cpu:                 59600m
  ephemeral-storage:   297841Mi
  hugepages-1Gi:       0
  hugepages-2Mi:       0

```

### 4.1.2 HAMi安装部署

HAMi调度器安装部署参见[HAMi官方文档](https://project-hami.io/zh/docs)。

### 4.1.3 使用示例

用户可以根据所需要的vHCU数量、HCU计算核心CU百分比和HCU显存容量，在k8s工作负载yaml配置文件内的resource limit字段的设置进行HCU资源申请（resource limit字段取值只能为整数）。

使用限制：每个container最多可以申请一张 vHCU，且不支持initContainers中申请vHCU。

#### 4.1.3.1 指定算力与显存申请vHCU

以下是一个k8s工作负载使用动态切分方式调用vHCU资源的示例：

```
apiVersion: v1
kind: Pod
metadata:
  name: vhcu-pytorch-demo
spec:
  containers:
    - name: vhcu-pytorch-demo
      image: image.sourcefind.cn:5000/hcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: [ "/bin/bash", "-c", "--" ]
      args: [ "sleep infinity & wait" ]
      resources:
        limits:
          hygon.com/hcunum: 1   #申请1个vHCU
          hygon.com/hcucores: 25  #指定申请vHCU算力为25%
          hygon.com/hcumem: 16384  #指定申请vHCU的显存为16384MB(16GB)
```

k8s工作负载成功运行后，可以进入对应容器运行 hy-smi virtual --show-device-info 命令查看vHCU分配情况。

```
root@vhcu-pytorch-demo:/# hy-smi virtual --show-device-info
Device 0:
    Physical Device: 0
    Compute units: 30
    Global memory: 17179869184 bytes
    Usage memory: 1900896256 bytes (11.06%)
    Dev busy percent : 76 %
```

#### 4.1.3.2 物理HCU卡申请

vHCU动态切分模式配合vHCU-Scheduler（或HAMi调度器）也可实现物理HCU卡的申请分配，若物理卡分配成功，对应物理卡将不会分配创建vHCU。

以下是一个k8s工作负载使用动态切分方式配合调度器申请分配物理HCU卡的示例：

```
apiVersion: v1
kind: Pod
metadata:
  name: hcu-pytorch-demo
spec:
  containers:
    - name: hcu-pytorch-demo
      image: image.sourcefind.cn:5000/hcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: [ "/bin/bash", "-c", "--" ]
      args: [ "sleep infinity & wait" ]
      resources:
        limits:
          hygon.com/hcunum: 2   #申请2个物理HCU（即整卡资源，该资源请求数量可以大于0）
```

#### 4.1.3.3 将任务分配给特定HCU

要将任务分配给特定的 HCU，只需在注释字段中添加 hygon.com/use-gpuuuid注解。

```
apiVersion: v1
kind: Pod
metadata:
  name: vhcu-pytorch-demo
  annotations:
    hygon.com/use-gpuuuid: "HCU-TPXS320016070601,HCU-TPXS320010040501" #指定以逗号分隔的HCU-UUID，并添加HCU前缀
spec:
  containers:
    - name: vhcu-pytorch-demo
      image: image.sourcefind.cn:5000/hcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: [ "/bin/bash", "-c", "--" ]
      args: [ "sleep infinity & wait" ]
      resources:
        limits:
          hygon.com/hcunum: 1   #申请1个vHCU
          hygon.com/hcucores: 25  #指定申请vHCU算力为25%
          hygon.com/hcumem: 16384  #指定申请vHCU的显存为16384MB(16GB)
```

相似地，要将任务禁止分配给特定的 HCU，在注释字段中分配 hygon.com/nouse-gpuuuid。

#### 4.1.3.4 将任务分配给指定HCU类型

要将任务分配给指定类型的HCU，只需在注解中添加hygon.com/use-hcutype注解。

```
apiVersion: v1
kind: Pod
metadata:
  name: vhcu-pytorch-demo
  annotations:
    hygon.com/use-hcutype: "HCU-K100_AI" #具体型号前添加HCU前缀
spec:
  containers:
    - name: vhcu-pytorch-demo
      image: image.sourcefind.cn:5000/hcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: [ "/bin/bash", "-c", "--" ]
      args: [ "sleep infinity & wait" ]
      resources:
        limits:
          hygon.com/hcunum: 1   #申请1个vHCU
          hygon.com/hcucores: 25  #指定申请vHCU算力为25%
          hygon.com/hcumem: 16384  #指定申请vHCU的显存为16384MB(16GB)
```

相似地，要将任务禁止分配给指定类型的 HCU，在注释字段中分配 hygon.com/nouse-hcutype。

## 4.2 Volcano

本文档基于 [Volcano](https://github.com/volcano-sh) 官方 vGPU 虚拟化机制，并结合 HCU 虚拟化用法，说明如何通过 光源 官方提供的 Volcano hcu-v1.15.0 调度器镜像，在 Kubernetes 中实现 HCU 虚拟化支持。适用于 AI / HPC 混合算力资源调度场景。

### 4.2.1 前提条件

| 项目       | 要求                |
| ---------- | ------------------- |
| Kubernetes | >= 1.23             |
| 容器运行时 | containerd / Docker |
| HCU 驱动   | >= 6.3.8            |

节点需提前完成 HCU 驱动与运行时环境安装，并确认以下命令可正常执行：

```
hy-smi
hy-smi virtual -show-device-info
```

### 4.2.2 架构说明

整体架构复用 Volcano GPU 虚拟化模型，通过 deviceshare 插件扩展支持 HCU 虚拟化：

```
+------------------+
|   Volcano Job    |
+--------+---------+
         |
         v
+------------------+
| Volcano Scheduler|
|   deviceshare    |
+--------+---------+
         |
         v
+-------------------+
| HCU Device Plugin |
|       HAMi模式     |
+--------+----------+
         |
         v
+--------------------------+
| HCU Driver + Runtime     |
+--------------------------+
```

### 4.2.3 环境准备

为包含 HCU 的节点打标签：

```
kubectl label node <node-name> hcu=on --overwrite
```

### 4.2.4. 安装 Volcano（使用 光源 官方镜像）

HCU 官方已在社区镜像站提供 Volcano hcu-v1.15.0 调度器镜像，版本与 HCU 虚拟化功能兼容。推荐使用此镜像部署。

#### 4.2.4.1 获取 Volcano 部署文件

从 Volcano 官方 GitHub 下载 volcano部署 的 manifests：

```
wget https://raw.githubusercontent.com/volcano-sh/volcano/master/installer/volcano-development.yaml
```

#### 4.2.4.2 修改调度器镜像

编辑 volcano-development.yaml，找到 volcano-scheduler 的 Deployment，将其镜像地址修改为 HCU 官方提供的volcano hcu-v1.15.0镜像：

```
# 原镜像可能为：
# image: volcanosh/vc-scheduler:v1.15.0
# 修改为：
image: harbor.sourcefind.cn:5443/hcu/admin/base/vc-scheduler:hcu-v1.15.0
```

若需同时调整 controller、admission 等其他组件镜像，可保持官方标签，一般无需改动。

#### 4.2.4.3  配置 Volcano 调度器支持 HCU 虚拟化

编辑 volcano-development.yaml，编辑 Volcano Scheduler 配置 ConfigMap，添加HCU虚拟化配置项。

```
apiVersion: v1
kind: ConfigMap
metadata:
  name: volcano-scheduler-configmap
  namespace: volcano-system
data:
  volcano-scheduler.conf: |
    actions: "enqueue, allocate, backfill"
    tiers:
    - plugins:
      - name: gang
      - name: priority
      - name: predicates
      - name: deviceshare
        arguments:
          deviceshare.VHCUEnable: true
          deviceshare.SchedulePolicy: binpack
          deviceshare.NodeLockEnable: true
          deviceshare.ScheduleWeight: 10
```

#### 4.2.4.4 部署 Volcano

```
kubectl apply -f volcano-development.yaml
```

#### 4.2.4.5 验证部署

```
kubectl get pods -n volcano-system
```

所有组件应处于 Running 状态，其中 scheduler 的镜像应为修改后的镜像。

### 4.2.5. 安装 HAMi 模式 HCU-Device-Plugin

volcano HCU虚拟化支持需要部署大于等于v2.4.0版本的HAMi模式HCU-Device-Plugin。
部署前需要修改k8s-hcu-plugin-hami.yaml中环境变量RESOURCE_MULTIPLE为true

```
      - image: image.sourcefind.cn:5000/hcu/admin/base/hcu-device-plugin:v2.4.0
        name: hcu-dp-cntr
        securityContext:
          privileged: true
        env:
          - name: "PULSE"
            value: "30"
          - name: "RESOURCE_REGISTER_STRATEGY"
            value: "hami"
          - name: "LOG_THRESHOLD"
            value: "INFO"
          - name: "LOG_OUTPUT"
            value: "true"
          - name: "LOG_VERBOSE"
            value: "2"
          - name: "POLICY"
            value: "0"
          - name: "RESOURCE_MULTIPLE"
            value: "true"
          - name: "NODE_NAME"
            valueFrom:
              fieldRef:
                fieldPath: spec.nodeName
kubectl apply -f k8s-hcu-plugin-hami.yaml
```

检查插件状态：

```
kubectl get pods -n kube-system | grep hcu-device-plugin-hami
```

请确保 k8s-hcu-plugin-hami.yaml 文件已准备就绪，可从 HCU 官方获取或联系技术支持。

### 4.2.6. 验证资源注册

检查节点上 HCU 相关资源是否已正确上报：

```
kubectl get node <node-name> -o yaml | grep -A20 allocatable
```

期望看到类似输出：

```
allocatable:
  hygon.com/hcunum: "8"
  hygon.com/hcumem: "512"
  hygon.com/hcucores: "800"
```

- hygon.com/hcunum：可切分的最大 vHCU 数量
- hygon.com/hcumem：可切分的最大显存（GiB）
- hygon.com/hcucores：可切分的最大算力（百分比）

### 4.2.7. vHCU 作业示例

创建一个使用 vHCU 的 Pod，通过 Volcano 调度：

```
apiVersion: v1
kind: Pod
metadata:
  name: vhcu-demo
spec:
  schedulerName: volcano
  containers:
  - name: hcu-app
    image: your-hcu-runtime-image
    command: ["bash", "-c", "hy-smi virtual -show-device-info && sleep 3600"]
    resources:
      limits:
        hygon.com/hcunum: 1     # 申请1个vHCU
        hygon.com/hcumem: 2     # 指定vHCU显存为2GiB
        hygon.com/hcucores: 50  # 指定vHCU算力为整卡的50%
```

提交作业：

```
kubectl apply -f vhcu-demo.yaml
```

进入容器验证虚拟化效果：

```
hy-smi virtual -show-device-info
```

输出示例：

```
Device 0:
  Actual Device: 1
  Compute Units: 60
  Global Memory: 2147483648 bytes
```

表示 vHCU 已成功分配并生效。

### 4.2.8. 常见问题与注意事项

#### 4.2.8.1 HCU 虚拟化限制

- 每个容器最多申请 1 张 vHCU
- 不支持在 initContainer 中使用 vHCU
- 不支持 HCU MIG 与 vHCU 同时开启

#### 4.2.8.2 调度策略建议

- 推荐使用 binpack 提高单卡利用率
- Volcano gang scheduling 可与 vHCU 混合使用

#### 4.2.8.3 资源未注册排查

若节点未显示 hygon.com/ 相关资源，请按以下步骤排查：

```
# 查看设备插件日志
kubectl logs -n kube-system <hcu-device-plugin-pod>

# 确认驱动正常
hy-smi

# 确认镜像版本与驱动匹配
```
